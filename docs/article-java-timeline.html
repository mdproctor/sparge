Already complete (Java 22, standard OpenJDK):
Project Panama (JEP 454) closes the native library access gap entirely. Java can now call C, C++, and Fortran code — the numerical foundation beneath NumPy and SciPy — without JNI boilerplate. No special JVM required.
The Valhalla inflection point (~Java 27–28):
Value types eliminate object boxing overhead, enabling contiguous memory arrays of primitives. This is the performance primitive that makes NumPy-class Java libraries possible. Preview expected Java 25–26; stable Java 27–28.
GraalVM and GraalPy:
GraalVM CE (open source) is already the foundation of Quarkus native compilation — widely adopted in production. GraalPy (Python on GraalVM) is available to these teams today and is maturing toward production readiness for Python interop workloads.
What remains after Java 28:
The scientific exploration culture — Jupyter-native workflows, the breadth of scikit-learn, data science pedagogy — has inertia beyond technical capability. The segmentation model (data scientists keep Python for exploration; Java dominates for applied application development) may persist as a rational division of labour even after technical parity is achieved.

⋯ Java 27 (September 2026) and Java 28 (March 2027) timelines are indicative based on the standard 6-month release cadence. Features marked speculative reflect JEPs in active development; versions may shift by one release. Java 21 and Java 25 are Long-Term Support releases.
